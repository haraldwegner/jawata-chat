# jawata-chat v0.2.13

**A brain picked in the chat is stored for the seat's next hire, and the card keeps what the run was started on; Agent Control shows each hire's calls and the earlier runs more plainly.** 0.2.12 was tagged but never published: its release run failed in one extension-host test that waited a fixed 50 ms for two background writes and read the first on a slow machine. This release carries 0.2.12 and a test that waits for what it checks. It needs jawata-mcp 4.6.13 and jawata-studio 4.6.17. The chat contract is 13.

## What changes

- **A pick is stored, not applied to the running hire.** The brain and model menu on an agent's card writes the seat's stored choice through the engine and says it applies from the next hire of that seat. The card's label stays what this run was started with, and the menu marks the stored choice. Every open chat is told when the choice changes.
- **An agent's fold shows its calls,** one line each, and the line under the agent's name marks only what to look at: a shell command on a Java file, a call that failed or was refused, a step with no passed gate, or calls the program did not name. A run with nothing to look at shows no figures.
- **Earlier runs show ten, then `more...`.** Each is one line with its task, agents and cost.
- **The brief is one line** (`Brief:` and its first line); the principal's earlier calls are no longer kept in a second list.
- **A transcript this agent does not have** shows *This agent has no transcript for this hire* and posts no error into the chat.

## Known limits

- Covered by the chat's tests and a replayed agent. **Not yet shown** in a real window with a live studio: a pick made in the card seen on the Seats page, and a real quiet hire.
- Up and Down in the message field moving by visual line is not in this release; it has not been tried in a real browser.
- Windows and macOS are run by CI, not by hand.
