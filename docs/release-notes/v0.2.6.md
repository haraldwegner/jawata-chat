# jawata chat and jawata Java v0.2.6

0.2.6 replaces 0.2.4 and 0.2.5. Both tags exist and neither has a release: the 0.2.4 run failed on a test that starts the engine's bridge and found no engine jar on the runner, and the 0.2.5 run failed on the test of the release workflow itself. 0.2.6 carries the same changes, and the release run now downloads the published engine for that test.

This release needs jawata-mcp 4.6.7.

## jawata chat

- **The list follows new output only while you are at the bottom of it.** Until now it jumped to the last line whenever output arrived, even while you were reading further up. Your own message takes you to the bottom. A test fails without the change.
- **With jawata-mcp 4.6.7 the model pick, Stop and the autocontinue button stay usable while a long job runs.** The engine held a lock during a pick that Stop and the option list needed; the fix is in the engine, and this chat sends nothing different. The freeze was reproduced and the fix tested in the engine's own tests with a stand-in agent; a live run of the chat against 4.6.6 (first message, model pick, tool, hire, Stop, a message after Stop) ended well, and nothing was clicked in a window by hand.
- **Esc is tested as bound to Stop while a turn runs,** in VS Code's own test runner. Pressing it in a real window was not tried.
- **Tests of the chat's own side of what jawata's agent sends** (a long answer of multi-byte characters on a stream cut in pieces; a model pick kept after the turn's option update) are green. They found no defect there, so the chat staying on "working" that was reported is not explained by anything in this package.

## Screens for a host (Eclipse, the studio)

- The Memory, Reporting, Seats and Workflow screens live in one host-free package, `@jawata/screens`, served on a port a host provides. Seats shows each seat's switch, brain (kept only after a one-word test run answered), Reset and its place in the workflow; main and btw list each brain the chat runs on with the models its own session offers, and a missing adapter is named with its install command.

## Known limits

- The scroll behaviour, the model list and the screens were tested in VS Code's own test runner and against stand-ins, not clicked in a window by hand.
- Not run on Windows or macOS.
